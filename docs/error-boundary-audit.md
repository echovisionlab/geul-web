# 오류 응답 조사 — 2026-10-09

웹의 잘못된 입력·권한 부족·요청 제한을 500으로 바꾸거나, 의존 서비스 장애를 401/404/성공 응답으로 숨기는 경로를 수정했다. 별도로 실패를 기본값으로 바꾸는 query 경로를 조사해 목록에 남겼다.

## 범위

`app/api`의 route 모듈 16개와 `lib/queries`의 비테스트 모듈 54개를 검색했다. 모든 route의 본문 파싱, 권한 검사, 의존 서비스 호출과 오류 변환을 확인했다. Query catch는 AST로 기본값 반환 후보를 추출했다. 운영 환경 전체에 장애를 주입하거나 모든 권한·데이터 조합을 재현한 조사는 아니다.

## 수정한 문제

| -------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 버전 기록·복원             | 401/403 외 오류를 모두 500으로 변환                                          | 입력 400, 없음 404, 충돌 409, 사전조건 422, 제한 429, 장애 503, timeout 504 분류 보존  |

MCP 안내 페이지·메뉴·회원 토큰은 이번 오류 조사에서 변경하지 않았다.

## 추가 발견: 기본값 반환 59곳

[후보 전체 목록](error-fallback-candidates.json)은 오류를 잡고 예외를 다시 던지지 않는 catch 블록이다. 이 숫자가 확정 버그 수는 아니다.

| 분류                                        | 개수 | 판단                                                                        |
| ------------------------------------------- | ---: | --------------------------------------------------------------------------- |
| 정상 빈 값과 실패를 구분하지 않는 추가 후보 |   33 | 화면의 오류 표시와 호출 계약을 함께 고쳐야 할 대상                          |
| 메타데이터·manifest·보조 파일 기본값        |   14 | 기본값으로 페이지 본문을 유지하려는 처리가 포함됨                           |
| 슬러그 검증 실패에서 허용하지 않음          |    8 | 검증 장애 때 사용 가능하다고 잘못 안내하지 않음. 실패 안내는 별도 확인 대상 |
| 반환값에 실패 상태가 있음                   |    3 | Label/Release 관리자 목록의 error, sitemap UNAVAILABLE                      |
| 권한 회수 뒤 이동 경로                      |    1 | 안전한 홈 이동 기본값                                                       |

33개 후보 중 다음 경로는 원인을 구분하지 않고 null/빈 자료를 반환하는 것이 코드에서 확인된다. 이번 PR에서 이 경로까지 모두 수정했다고 주장하지 않는다.

- `getArtistView`, `getLabelPublic`, 관리자 `getPage`, `getUserProfileView`, `getProgramEventSeriesView`: 장애를 자료 없음으로 처리할 수 있다.
- Form 설정·초기 편집 데이터·제출 내역 조회: 조회 실패 또는 JSON 손상을 null로 바꾼다. 특히 초기 편집 데이터 fallback은 저장 동작까지 함께 검토해야 한다.
- 관리자·공개 목록·회원 게시글·일부 selector 조회: 장애를 빈 목록 또는 0건으로 표시할 수 있다.
- 사이트 설정과 메뉴 조회: 인증/권한 거부와 서비스 장애가 같은 기본값으로 전달될 수 있다.

Query 후보의 일괄 throw 변경은 클라이언트의 오류 표시·재시도·편집 초기화 계약을 바꾼다. 이 보고서에 위치와 함수·반환값을 남겼으며, 현재 PR은 HTTP/MCP 오류 경계에서 재현하고 검증한 수정만 포함한다.

## 그대로 유지한 경로와 제한

- RPC 프록시는 원본 응답 상태를 전달하며 fetch 실패를 502로 응답한다. 업로드 프록시도 외부 fetch 실패를 502로 처리한다.
- RPC 프록시의 요청 본문 읽기 실패는 400, 외부 응답 buffer 읽기 실패는 502로 수정하고 회귀 테스트를 추가했다.
- 클라이언트 오류 보고 API는 잘못된 JSON/형식/크기에 400/415/413, 제한에 429를 반환한다. 요청 본문 stream 읽기 실패도 400으로 처리하도록 수정했다.
- 로그아웃은 외부 로그아웃 URL 조회 실패 시 로컬 쿠키를 지우고 홈으로 이동하는 기존 사용자 동작을 유지한다.
- 렌더러·알 수 없는 서버 실패는 500과 안전한 메시지를 반환한다. HTTP 상태를 일괄 400으로 바꾸지 않았다.
- 엄격한 세션 조회는 세션 HTTP API와 OG 권한 확인에 적용했다. 기존 Server Component의 null fallback을 전역적으로 바꾸지 않았다.

## 검증

수정한 HTTP 경계에서 null·배열·잘못된 JSON, Author/익명, 권한 거부, 요청 제한, 의존 서비스 장애, timeout, 실제 내부 실패를 테스트했다. 미디어 API는 공유 링크와 일반 조회를 모두 확인했다. 세션 장애 응답에서 쿠키를 삭제하지 않는 것도 검사했다.

- 웹 전체: 866개 테스트 파일, 5,119개 테스트 통과.
- 타입 검사와 변경한 코드의 ESLint 통과.
- 그 뒤 추가한 pagination/restore 입력 경계 17개 테스트와 RPC/오류 보고 본문 실패 테스트는 별도로 실행했다.
- PR CI에서 전체 웹 검사와 production/Storybook 빌드를 확인한다.

Geul API의 관련 보고서와 수정은 `echovisionlab/geul-api` PR #100에 있다. OpenDiscogs gateway는 인증 장애 503·제한 429·자료 없음 404를 유지했고, Go OpenDiscogs API의 HTTP/관리 테스트도 통과했다.
