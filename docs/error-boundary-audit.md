# 오류 응답 조사 — 2026-10-09

웹의 잘못된 입력·권한 부족·요청 제한을 500으로 바꾸거나, 의존 서비스 장애를 401/404/성공 응답으로 숨기는 경로를 수정했다. 실패를 기본값으로 바꾸던 Query 후보 33곳과 추가 Server Action 47개도 호출 화면과 함께 수정했다.

## 범위

`app/api`의 route 모듈 16개와 `lib/queries`의 비테스트 모듈 54개를 검색했다. 모든 route의 본문 파싱, 권한 검사, 의존 서비스 호출과 오류 변환을 확인했다. Query catch는 AST로 기본값 반환 후보를 추출했다. 운영 환경 전체에 장애를 주입하거나 모든 권한·데이터 조합을 재현한 조사는 아니다.

### 화면과 저장 계약

- 관리자 통계는 장애 때 0건으로 표시하지 않는다. 설정 조회 실패는 기본 설정 편집·저장 폼을 열지 않는다. 필수 설정 payload가 없을 때도 오류로 끝내며 로더에 갇히지 않는다.
- 메뉴·정책 기록·selector 화면은 공통 `QueryErrorAlert`로 안전한 상태별 제목과 필요한 로그인·재시도를 표시한다. 편집기 전체를 unmount하지 않아 작성 중인 필드 값을 유지한다.
- 공개 자료의 실제 `NotFound`는 기존 null 계약을 유지한다. 공개 Label/Event Series의 권한 거부는 기존 비공개 자료 숨김 계약을 유지한다. 장애와 timeout은 자료 없음으로 바꾸지 않는다.
- 폼 초기 schema와 제출 데이터는 JSON 및 Zod 구조 검사를 통과해야 한다. 손상된 저장 데이터를 빈 협업 편집기로 초기화하지 않는다.
- 확인 장애를 슬러그 중복으로 안내하지 않는다. 검증에 실패한 새 슬러그는 자동 저장하지 않는다.
- 메뉴 대상·공개 Page 설정 selector의 Server Action은 실패 상태를 직렬화한 `QueryResult`를 반환한다. 중첩 Action에서도 상태를 보존하며 내부 RPC 진단 문자열을 브라우저에 전달하지 않는다. 메뉴 Category/Tag 대상의 관리자 목록도 같은 계약으로 수정했다.
- Server Component 오류는 운영 Next.js가 원문과 사용자 속성을 제거하므로, 상태와 임의 식별자만 포함한 digest로 화면의 상태 분류를 보존한다. 이는 오류 화면의 표시 계약이며 Next 렌더링 응답 자체의 HTTP 상태를 변경하지 않는다. HTTP API 경계는 별도 분류된 HTTP 응답을 사용한다.
- Storybook `Core/Feedback/QueryErrorAlert`에 실제 공통 컴포넌트의 장애·권한·로그인 미리보기를 추가했다.

### Server Action 후속 조사

[Action 후보와 처리 결과](server-action-error-candidates.json)는 최초 함수·줄·반환값을 보존한다. 원래 줄 번호는 최신 위치가 아니다.

- null·빈 배열·빈 목록 객체로 모든 예외를 덮던 39개 조회·미리보기 Action을 `QueryResult`로 변경했다. 추가 객체형 목록 7개와 폼 비밀번호 검증도 수정해 총 47개이다.
- 브라우저와 Server Component 호출부는 결과를 unwrap한다. 실제 빈 성공은 그대로 유지하고, 실패는 오류 화면·공통 알림 또는 기존 댓글 실패 알림에 전달한다. 공개 목록이 무한 스켈레톤이나 “없음”으로 남지 않도록 초기 실패를 분기한다.
- 카탈로그·회원 selector, 참여자·통계·관리 화면에서도 실패를 표시한다. 편집기와 선택된 값을 유지하며 재조회할 수 있다. 캠페인 미리보기는 마지막 HTML을 유지하면서 오류를 표시하고, 오래된 응답이 최신 미리보기를 덮지 않는다.
- Release 관계·트랙 갱신은 성공한 부분만 반영하고 실패한 부분의 기존 값과 변경 중인 필드를 유지한다. 실패 알림과 재시도를 제공한다.
- 세션 목록은 엄격한 세션 조회를 사용한다. 인증 서버 장애를 빈 세션 목록이나 로그인 필요로 바꾸지 않는다.
- 조건부 fallback 8곳은 기존 NotFound·접근 제한 계약을 유지했다. 선택 Client 조회는 위 47개에 포함되며, 나머지 7개 상세·미리보기 Action은 그 외 오류의 상태를 운영 Next digest에도 보존한다.
- Mesh 최적화의 없어진 원본 후보, 이미 삭제된 파일의 삭제, 삭제된 폴더 목록은 명시적 없음·멱등 처리 계약이다. 성공/실패 필드가 있는 mutation, 보조 metadata, 로그아웃의 로컬 처리와는 구분했다. 이 조사는 모든 mutation의 오류 문구까지 재작성한 작업은 아니다.

## 그대로 유지한 경로와 제한

- RPC 프록시는 원본 응답 상태를 전달하며 fetch 실패를 502로 응답한다. 업로드 프록시도 외부 fetch 실패를 502로 처리한다.
- RPC 프록시의 요청 본문 읽기 실패는 400, 외부 응답 buffer 읽기 실패는 502로 수정하고 회귀 테스트를 추가했다.
- 클라이언트 오류 보고 API는 잘못된 JSON/형식/크기에 400/415/413, 제한에 429를 반환한다. 요청 본문 stream 읽기 실패도 400으로 처리하도록 수정했다.
- 로그아웃은 외부 로그아웃 URL 조회 실패 시 로컬 쿠키를 지우고 홈으로 이동하는 기존 사용자 동작을 유지한다.
- 렌더러·알 수 없는 서버 실패는 500과 안전한 메시지를 반환한다. HTTP 상태를 일괄 400으로 바꾸지 않았다.
- 엄격한 세션 조회는 세션 HTTP API와 OG 권한 확인에 적용했다. 기존 Server Component의 null fallback을 전역적으로 바꾸지 않았다.

## 검증

수정한 HTTP 경계에서 null·배열·잘못된 JSON, Author/익명, 권한 거부, 요청 제한, 의존 서비스 장애, timeout, 실제 내부 실패를 테스트했다. 미디어 API는 공유 링크와 일반 조회를 모두 확인했다. 세션 장애 응답에서 쿠키를 삭제하지 않는 것도 검사했다.

- 이전 HTTP 경계 배포: 웹 전체 866개 테스트 파일, 5,119개 테스트 통과.
- Query 후속 수정: 33개 함수에 인증·권한·입력·제한·장애·timeout·내부 실패·전송 실패를 주입한 회귀 테스트와 실제 NotFound 계약을 검사했다. 손상 폼 데이터·필수 설정 누락·실제 빈 성공·슬러그 자동 저장 차단·Server Action 직렬화·편집 입력 보존도 검사했다. 전체 후속 검사 871개 파일·5,441개 테스트가 통과했다. 그 뒤 추가한 운영 Next 오류 직렬화 8개 검증과 Query 관련 309개 검증도 별도 통과했다. 최종 전체 검사는 PR CI에서 다시 실행한다.
- Action 후속 수정: 전체 874개 파일·5,781개 테스트 통과. 47개 Action의 직렬화·분류 검증 329개와 조건부 상세 Action 7개의 상태 보존·NotFound 검증 42개(합계 371개)도 통과했다. 마지막 42개 추가 검사는 별도로 실행했으며 최종 전체 검사는 PR CI에서 확인한다.
- 타입 검사와 변경한 코드의 ESLint 통과.
- 그 뒤 추가한 pagination/restore 입력 경계 17개 테스트와 RPC/오류 보고 본문 실패 테스트는 별도로 실행했다.
- PR CI에서 전체 웹 검사와 production/Storybook 빌드를 확인한다.

Geul API의 관련 보고서와 수정은 `echovisionlab/geul-api` PR #100에 있다. OpenDiscogs gateway는 인증 장애 503·제한 429·자료 없음 404를 유지했고, Go OpenDiscogs API의 HTTP/관리 테스트도 통과했다.
