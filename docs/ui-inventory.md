# Route-to-UI Inventory

Snapshot: Member and Account cutover working tree, updated 2026-08-04.

## Component Test Ownership

Storybook renders Core and prop-driven Feature UI only. Route, query, mutation, collaboration, and
live-backend controllers are not Storybook subjects. Controller behavior stays in focused unit
tests; the repository has no production E2E suite.

Storybook is limited to fixed Core and prop-driven Feature UI states. Editor runtimes, route
compositions, provider-backed surfaces, and page/controller harnesses are not Storybook subjects.

- Story modules contain no co-located `play` functions or React controller hooks. CI validates the
  pure registry and builds the visual catalog; Vitest owns every behavior assertion.
- Stories own their controls and descriptions explicitly. Automatic React prop extraction is
  disabled because this catalog does not publish generated component API docs; application modules
  are therefore not scanned by `react-docgen` during the CI build.
- The repository has no Storybook browser runner, Playwright dependency, standalone browser suite,
  manual-story exception, or runtime/page story registry.
- HEIC decode/crop, navigation, editor, media runtime, viewport geometry, WebGL, and provider flows
  are deterministic Vitest concerns or manual product verification, not catalog entries.
- `Feature/Metadata/Label OG Logo Preview` is the network-independent visual authority for the
  title-free 1200×630 Label canvas. Its controls vary the production-pixel contain box and background,
  while one comparison renders horizontal, square, vertical, and transparent-padding logo ratios.

External-video coverage added by this snapshot:

- `Feature/Media/External Video` uses local `data:` iframe fixtures for fixed YouTube, Vimeo,
  long-caption, narrow, and print visual states. Live-provider stories are not registered.
- `Feature/Editor/External Video Insert` covers empty, invalid, and valid URL dialog states.
- `Feature/Editor/External Video Preview` covers exact standalone-link promotion inside Post/Page
  editors, both resize handles, alignment/aspect-ratio persistence, link editing, nested/mixed URL
  fallback, and the Work/Event exclusion with a local `data:` iframe.
- Focused generated-renderer tests cover the same standalone paragraph link in the public Post/Page
  projection. There is no separate durable YouTube block or duplicate YouTube slash command.
- `Feature/Page Blocks/External Video` covers public output, canvas preview, settings, and Columns
  nesting with local iframe fixtures.
- `Page/Public/Post External Video` covers standalone promotion and mixed-link fallback. Unit tests
  enforce the same promotion boundary for Page rich text and prove Work/Event remain ordinary links.

Localized rich-text editors use one source document and locale-scoped target overlays across Post,
Page, Work, and Program Event. Source/target overlays own their locale text, captions, and image alt,
while only the source room may change base block structure, media `fileId`/name, alignment, and size.
Source and target locale rooms are editable only under the owning-domain permission. Target locales join
their own Collaboration room and expose locale text, comparison, and explicit Create/Regenerate controls but
never replacement upload or shared-structure controls. A locale either has a target document or it does not;
there is no target lifecycle or status surface. Target revision is an internal CAS value only,
with no target Version, history, or restore UI. Page top-level and Columns-nested rich text use the matching
`section-{id}` fragment. Authoring is withheld until the routed source or target collaboration provider is synced.

Post, Page, and Work source editors expose source version history as a read-and-restore surface. There is no
manual snapshot action or Web snapshot route: collaboration checkpoints a long editing session
after 30 minutes and finalizes it after the last contributor disconnects. Each row renders every
recorded contributor in order by its required preserved nickname; the UI does not expose Member UUID as a name.
Target locale rooms expose the existing target document and collaboration state; target revision remains an
internal CAS value with no Version, history, or restore surface.
Rows with no contributor data use a neutral
system-or-earlier-version label, and every row displays the snapshot's source locale. Restore remains available
subject to the existing authoring lock after the current source locale has resolved.
The shared confirmation identifies the restored document as the source. Restoring source leaves every existing
target document unchanged, readable, and editable, and starts no generation. A queued or running generation tied
to its saved request artifact continues independently; Create/Regenerate remains explicit for one locale
or an explicitly selected locale set. A successful restore reloads the source collaboration room, refetches translation
entries and jobs, refreshes the latest locale-scoped OG generation, and refreshes server metadata. Failure keeps
the drawer and confirmation open and displays only a bounded authorization or restore error.

Target editor routing is entity-centric rather than role-centric. Home Page, Post, Page, Work,
Artist, Release, Label, Form, and Program Event use the public route family plus `edit=true`, but the canonical
editor URL uses the immutable entity UUID rather than the mutable public slug. Every authorized Site Admin, Author,
Collaborator, Owner, or Manager reaches the same route. A valid but unauthorized
Session receives `404`. Admin list/create routes may remain, but duplicate
`/admin/{domain}/{id}` editors and the complete `/my/forms` family are removed without redirect
aliases. Authorized legacy slug editor URLs resolve through the manage boundary and redirect to the UUID editor URL;
public view URLs continue to prefer the slug. Page is the root-path exception: `/{slug-or-uuid}` reads and
`/{uuid}?edit=true` is the canonical editor URL.
Across slug-owning editors, the shared authoring header keeps an empty in-progress title as a local draft and shows
an entity-specific `Untitled {entity}` placeholder. Empty drafts do not emit title mutations or error notifications;
the next non-empty value resumes title persistence. Existing entity title edits never generate or mutate the slug:
slug changes are explicit URL-field edits only, while create flows may still generate the initial slug once.
Page slugs may equal `posts`, `works`, `artists`, `releases`, `labels`, `forms`, or `events`; each exact
one-segment path resolves only that Page and returns `404` when absent, with no collection fallback.
Plural entity detail routes remain independent at two segments. Form builder, settings, translations, and submissions are tabs on the single
`/forms/{id}?edit=true` route. `/my/works` may retain credited Work read-only discovery but removes
its editable Work tab.

This inventory covers every currently served `app/**/page.tsx` and every `app/**/layout.tsx`. Route groups such as `(general)` and `(edit)` are omitted from URL paths. The grouping below is by URL family, so protected edit pages under `(general)` remain in Public.

The controller boundary and rendered UI were established from each page's actual imports, body, JSX, local components, and re-export target. Name similarity alone was not used. Metadata-only calls are omitted unless they also affect body rendering.

## Reading The Inventory

- **Current UI -> candidate** names the components the route actually renders. `Extract X` means the page currently mixes controller state and presentation, so `X` is a proposed prop-driven Storybook boundary rather than an existing export.
- **Story** records exact or directly nested feature stories reachable through the inspected render path. Primitive-only stories such as `Core/Button` are not route coverage.
- Direct page compositions now cover the Public shell, Admin shell, Public user profile, My profile,
  My artists, and My settings surfaces. Feature stories continue to cover nested controls and editors; rows below
  record the exact direct or nested coverage so missing route work remains visible.
- **Missing states** means missing dedicated Storybook coverage, not necessarily missing runtime behavior.

## Styling ownership

Core and Mantine semantic primitives are the first styling boundary. Use Mantine props for simple
layout; use `classNames` with a CSS Module when a component needs selectors, state, pseudo-class,
responsive, or NodeView styling. Global CSS is limited to root, vendor, print, materialized prose,
and externally generated DOM. Component-specific global `.mantine-*` overrides are not part of the
UI contract.

CDN Noto Sans plus the active KR/JP/SC/TC/Arabic profile is the sans and heading family; Noto Sans
Mono is the monospace family. Mantine blue owns interaction while Site Settings `primary_color`
owns branding through `--geul-brand-color`; danger uses semantic red. Public and Tiptap basic
document blocks share Mantine typography and spacing tokens through `lib/styles/document-content.css`,
while `.prose` is only a generated public-DOM hook and editor-only chrome stays in Feature CSS Modules.

p5.js, Three.js, and Shader blocks share one engine-neutral title and one runtime/source action
row in authoring and public views. Authoring edits a locale-owned custom title; public renders that
localized title and falls back to the engine label. Both surfaces place that title in the same
title-only header, without authoring-only inset, underline, or color. Both surfaces use one Chevron to
expand or collapse Monaco beneath the preview. Authoring Apply persists through the document/Yjs boundary;
public Apply changes only local component memory and exposes no separate temporary-copy action.
Stop/run, restart, and original reset use transparent Core IconButtons with tooltips. Authoring and
public rendering use one matching outer box with no body/figure padding or title-row bottom border.

p5.js camera, microphone, motion, MIDI, gamepad, serial, location, and Bluetooth capabilities belong to
Shared block structure and are not locale copy. Device-capable blocks do not auto-run: their declared device
indicators are visible and an explicit Run
opens the configured cookie-less runner origin on a different registrable domain, where the browser owns the
permission decision. The iframe has no same-origin sandbox grant and no same-origin `srcdoc`; authoring and
public temporary source arrives only after an exact runner-origin/channel handshake. Stop, hidden-tab,
unmount, error, and disposal paths close acquired MediaStream, MIDI, serial, and Bluetooth GATT resources.

Map blocks always render the normal aspect-ratio canvas in Tiptap and public views. Their stored
center and zoom remain usable with zero Map Place markers; place management is an optional map
interaction. Public map captions follow the authoring caption directly below the map with the same
compact spacing and left alignment, independent of the map block alignment.

State profiles used in the final column:

- **Static**: default, long content, narrow viewport, and wide viewport.
- **List**: loading, load failure, empty, populated, filtered no-results, pagination, and mutation failure.
- **Detail**: loading, load failure, not found, forbidden, sparse data, and full data.
- **Editor**: loading, load failure, not found, forbidden/read-only, pristine, dirty, validation, saving, save success, and save failure.
- **Flow**: initial, pending, success, failure, and retry.
- **Localized**: requested locale with an existing target document, missing target with source fallback, long translated copy, and RTL.
- **Share**: no token, valid token, invalid token, and expired token.

한 번 클릭은 선택, 두 번 클릭·Enter는 폴더 열기 또는 File Preview다. 우클릭 메뉴,
Cmd/Ctrl toggle, Shift range와 빈 영역 drag-box selection을 지원한다. File-only selection은
현재 batch move/delete를 제공하며 mixed 또는 multi-folder mutation은 원자 계약 전까지 만들지
않는다. Icon은 작은 고정 cell과 filename만 사용한다. List는 Core DataTableView의 checkbox,
전체 선택, sortable header와 row를 사용하고 File Feature가 Cmd/Shift·우클릭·열기를 주입한다.
검색·MIME filter·sort·batch action·view switch는 borderless File header에 있다. 검색어가 없으면
현재 folder를 complete snapshot으로 탐색한다. 검색어가 있으면 현재 folder subtree와 모든 File 중
범위를 선택해 File·folder path를 포함한 paginated 결과로 전환한다. 검색을 지우면 이전 folder와 browse view로 복귀한다. 검색 상태의
하단 status는 선택 상태와 무관하게 File·folder 합계 total을 유지한다. 폴더 목록은 공개 pagination
없이 단일 snapshot으로 최대 10,000개를 표시하며 초과·중복·불완전 응답, missing과 empty를 구분한다. List Usage는 권한 필터된 상태 icon만 표시하고 상세는 허용된 domain link를 열거한다. Site Settings slot link는 Admin에게만 보인다. File Preview는 centered Quick Look modal과 Post/Page 공통 AudioPlayer·VideoPlayer를 사용한다. Audio는 HLS
우선+waveform 전용이며 spectrogram은 표시하지 않고, Video는 HLS 우선+poster를 사용한다.
두 player는 square surface, background-free control, site primary accent와 같은 loading UI를
공유한다. Video.js의 기본 navy skin은 사용자 UI로 노출하지 않는다. Audio·Video·Release Track의
원본 다운로드는 공통 tooltip icon이며 player가 있으면 player control에 둔다. Attachment는 같은
icon을 제목·metadata와 함께 얇은 square border 안에 둔다.
Active usage가 있으면 deletion modal이 first 5와 전체·domain count를 보여주고 삭제를 막는다.
Locale 변경은 File Manager control과 실패 상태 전체에 적용한다. Folder·filename은 사용자 content이므로 번역하지 않는다.

Rich-text editor는 Post·Page·Work·Program Event에서 MIME과 무관한 `file` block과 `파일 첨부` 메뉴 하나를
사용한다. Add dialog의 upload와 File picker는 여러 File을 선택할 수 있고 replace는 하나만 선택한다.
개별 제한을 넘거나 지원하지 않는 upload는 제외하고 나머지를 순서대로 block으로 만든다. 검색은
현재 folder subtree와 모든 File 중 선택한 범위의 matching File·folder를 표시하고 각 논리 path를 보여준다. Folder 결과는 열 수 있으며
허용 MIME·크기 또는 media 실패 상태로 사용할 수 없는 File은 결과에서 제거하지 않고 disabled로
둔다. 상태는 선택 가능 개수와 무관하게 전체 검색 결과 수를 유지한다. 선택 가능한 File UUID만
owning editor controller에 반환하며 Controller가 shared `file` block의 참조와 표시 metadata를
갱신한다. Viewer와 editor는 canonical MIME으로 image·audio·video·일반 file UI를 고른다.
Upload, folder, filename과 move mutation은 File Manager controller가 소유한다. Picker의 Preview는
mutation 없이 shared Quick Look modal을 열고, featured image와 Site Settings slot mutation은 picker가
직접 수행하지 않는다.

## Admin

Every route below also passes through the Admin layout's session and role guards.

### Translation authoring

Post, Page, Work, Program Event, Release, Artist, Label, Email Template, Campaign, Form, Privacy, and Terms
expose an editable source locale plus locale-scoped target editors.
Source and target locale rooms are editable only under the owning-domain permission. Each target editor
hydrates the shared source structure but saves only locale-owned text through its own Collaboration room;
its target revision is an internal CAS value, not a Version/history/restore UI. It has no source-structure,
shared setting, or File mutation command. Owning-domain editors and delegated MCP actors use the same target
save boundary. Archived Post, Work, and Program Event authors see source/target rooms, presence, cursor, and
conversation read-only; Admin can edit. A locale either has a target document or it does not, with no separate
target lifecycle or status UI. Source changes retain immediate/debounced persistence, leave every existing target
document unchanged, readable, and editable, and never request AI. Source/original view is a normal locale-control
selection with no translation warning. A queued or running generation keeps using its saved request artifact when
the source changes and applies only stable units that remain in the current graph.

The target-editor contract is not yet activated for Menu, which currently exposes a read-only target preview. Post
Series title and description use the exact locale-scoped Collaboration room: existing target values are editable,
missing units display current source fallback, and explicit empty stays empty; slug and other shared fields remain
source-only. Email Layout target rooms use stable visible-text and `alt`/`title`/`aria-label` units: missing values
display current source fallback, explicit empty stays empty, and only the source locale mounts the raw HTML editor.

Translation panels render the target document when it exists and an explicit Create action when it does not;
absence is not a lifecycle status, and the panel exposes no target-status surface. Regenerate is an
explicit action for an existing target. Create/Regenerate requires one locale or an explicitly selected locale
set; an empty list never means all. The job UI shows only persisted `queued|running` work and exposes cancel while
the job remains active. Failure and timeout create no terminal row or same-job retry surface; recovery is a new
explicit Create/Regenerate request from the then-current source. A completed Create/Regenerate replaces the whole
target even if a Member/MCP edit committed after the request and applies the saved request artifact against the
current stable-unit graph. Target CAS remains internal and no prior target restore exists. When the owning root is
public, including a Post with PUBLISHED or ARCHIVED
status, public read serves the requested target document whenever it exists; only a missing target document uses
source fallback. The normal locale control can select the source/original without a warning and does not label a
target as automatic, AI-authored, or manually authored.
Terms and Privacy add the non-dismissible, print-visible `참고 번역이며 원문이 우선합니다` notice to
translated active, preview, history, and share documents.

Localized OG metadata follows the same atomic selection. Page, Post, Work, Artist, Form, Series,
Terms, and Privacy use only an asset generated for the selected target document revision. While that asset is
pending or its generation fails, the existing target text remains selected and metadata omits the image instead
of borrowing source, Featured, or Site OG images. Only a missing target document returns the complete source text

The audio-transcoder groups include a network-independent CI runtime smoke story, a manual
exact-version jsDelivr Hands-on story, and explicit format-specific output controls for WAV, AIFF,
AAC, Ogg Opus, MP3, and FLAC. Loading/error and `Converting with progress` stories use Core progress
inside the existing output-settings and conversion-queue regions. Supported formats and advanced processing
notes use compact Core disclosures so the drop target and output settings retain short primary instructions.
Focused model, controller, and view unit tests cover WAV float/integer precision, bitrate-dependent MP3 rates,
Ogg automatic 48 kHz selection, the 384 kHz pass-through boundary, multichannel and preserve-source rejection,
mixed-queue disclosure, current-batch results, and visible preset resets. CI never fetches a third-party codec asset.

Media download-policy stories use local/data media fixtures for visual policy states and retain browser interaction
coverage for compact Audience display, portal options, production-header save feedback, and server-search pagination
beyond the first page. Focused unit tests cover loading, auto-save serialization and rollback, Audience-list failure,
and empty restricted fail-closed display after Audience archiving.
The integrated editor surface mounts the inline Core Download access control for every persisted Image, Audio,
Video, or General `file` Block on Post, Page, Work, and Program Event. Representative browser stories cover
persisted Post Audio and Video, persisted Page General File, and a narrow Page fixture; focused
`MediaDownloadPolicyPanel` tests map all four owner types to the same exact `reference_path=file` relation and keep
only unpersisted media hidden. Release Track editor coverage mounts the same relation policy control when an
original File exists. Audio follows the same automatic upload-processing model as Video; editor trim and loudness
controls are intentionally absent.

Editor upload progress stories run the production `useFileUpload` XHR path and render the actual
`MediaProcessingSurface` with Core Progress. The Feature controller keeps one upload activity
monotonic when local XHR, realtime lifecycle, or retry updates arrive out of order. Reload/resume
starts from the server-returned completed-part baseline;
only a server-declared new upload or an explicit replacement starts again at zero. Terminal upload and
processing failures show stable user-facing copy without exposing backend/provider details; an expired pending
upload is removed through the production runtime projection. The immersive-scene editor runs one representative
production GLB upload-to-clear lifecycle, while its format, cancellation, texture, and deletion matrices remain
focused component tests. Hook and component tests cover same-attempt retry, stale prior-activity updates,
resumable reload, and new-attempt reset.
Editor direct multipart media verifies the authenticated same-origin prefix, gets a same-origin part presign,
performs the credential-free object PUT, and confirms the part through the same-origin API. A successful editor
upload writes only its completed File UUID into the collaborative block; the renderer obtains current delivery
metadata independently.

Core stories validate primitives only and are intentionally not counted as route or Feature-composition coverage.
